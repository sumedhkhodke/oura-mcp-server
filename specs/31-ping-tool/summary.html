31-ping-tool

Add a ping MCP tool to the Oura server

The change: Add a lightweight MCP tool named ping to the Oura server that requires no credentials and makes no API calls. The tool serves as a connectivity check, returning a JSON object with three fields: the server name ("oura-mcp-server"), the current package version, and the current UTC timestamp. This is a throwaway feature to test the Factorial end-to-end workflow.

🎯 Riskiest Assumptions

A2: Server name is "oura-mcp-server"
The FastMCP instance name from server.py:30 is the source of truth. If wrong: one-line change.
A5: Tool must be async
All existing MCP tools are async. If wrong: MCP protocol may reject a sync tool.
A7: README placement is separate from data tools
Ping serves a different purpose (health check). If wrong: placement is cosmetic, always movable.

❓ Open Questions

Q1: Timestamp precision?
Proceeding as: Full microsecond precision from datetime.now(timezone.utc).isoformat(). Revisit if clients need coarser precision.
Q2: README entry location?
Proceeding as: Single row in tools table. Revisit if table structure changes.

🔧 Tool Implementation

The ping tool is a simple async function that reads immutable server state and the current time.

@mcp.tool
async def ping() -> dict[str, str]:
    """Check server availability and version."""
    return {
        "server": mcp.name,           # "oura-mcp-server"
        "version": __version__,        # from __init__.py
        "time_utc": datetime.now(...).isoformat()
    }
